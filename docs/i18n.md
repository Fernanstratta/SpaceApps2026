# Bilingüismo (español / inglés)

## Cómo se elige el idioma

Las URLs públicas llevan el idioma como prefijo: `/es/...` y `/en/...`. En inglés los slugs también se traducen
(`/es/portal-educativo` ↔ `/en/educational-portal`). Los ids de temas y submódulos son iguales en ambos idiomas.

Si alguien abre una URL **sin** prefijo (`/`, `/portal-educativo`, un enlace antiguo…), antes de montar React
`src/i18n/bootstrap.ts` elige el idioma y reescribe la URL **una sola vez**. Usa `history.replaceState`, así que no
recarga la página ni añade entradas al historial. Prioridad:

1. **Prefijo en la URL** (`/en/...`): se respeta siempre y nunca se redirige, así que no puede haber bucles.
2. **Elección guardada**: lo que el usuario eligió en el selector «ES / EN» (`localStorage` → `terranauta-lang`).
3. **País**: español si el país es hispanohablante (`SPANISH_SPEAKING_COUNTRIES` en `src/i18n/config.ts`) y
   en cualquier otro caso inglés.
4. **Idioma preferido del navegador** (`navigator.languages[0]`): `es-*` → español, `en-*` → inglés.
5. **Español** por defecto.

No se pide permiso de ubicación (GPS): el país sale de la IP y lo aporta el servidor.

## Detección por país: qué hace falta en el backend

Hoy el sitio es estático (Vite), así que **no hay país** y se usa el idioma del navegador (paso 4). Para activar
el paso 3 basta con **una** de estas dos opciones. Ninguna requiere cambiar el frontend.

### Opción A: endpoint JSON (la más simple)

1. Crear `GET /api/geo`, que responda:

   ```json
   { "country": "MX" }
   ```

   Usar ISO 3166-1 alfa-2. Si no se conoce el país, responder `{ "country": null }`; valores como `XX` o `T1`
   también se tratan como desconocidos.

2. Definir la variable en el build del frontend (ver `.env.example`):

   ```bash
   VITE_GEO_ENDPOINT=/api/geo
   ```

El frontend solo llama al endpoint cuando la URL no trae idioma y el usuario no eligió uno. Espera como máximo
1,5 s y, si falla o tarda, usa el navegador.

### Opción B: inyectar el país en el HTML (sin petición extra)

Al servir `index.html`, rellenar la meta que ya existe:

```html
<meta name="terranauta-country" content="MX" />
```

(o definir `window.__TERRANAUTA_GEO__ = { country: 'MX' }` en un `<script>` antes del bundle).

### De dónde sacar el país según el hosting

| Hosting / servidor        | Dato disponible                                       |
| ------------------------- | ----------------------------------------------------- |
| Cloudflare (proxy)        | Cabecera `CF-IPCountry`                               |
| Vercel                    | Cabecera `X-Vercel-IP-Country`                        |
| Netlify (Edge Functions)  | `context.geo.country.code`                            |
| AWS CloudFront            | Cabecera `CloudFront-Viewer-Country` (hay que activarla) |
| Servidor propio (Node…)   | Base de datos GeoIP (p. ej. MaxMind GeoLite2) con la IP |

Ejemplo mínimo con Express detrás de Cloudflare o Vercel:

```js
app.get('/api/geo', (req, res) => {
  const country = req.get('cf-ipcountry') ?? req.get('x-vercel-ip-country') ?? null;
  res.set('Cache-Control', 'private, no-store'); // depende de cada visitante
  res.set('Vary', 'CF-IPCountry, X-Vercel-IP-Country');
  res.json({ country });
});
```

> El servidor también debe devolver `index.html` para cualquier ruta del SPA (`/es/...`, `/en/...`), como ya
> indica el README.

## Probar la detección

- **Simular un país:** añadir `?country=MX` o `?country=US` a una URL **sin** prefijo, p. ej.
  `http://localhost:5173/?country=US`. Funciona con cualquier hosting y sirve solo para pruebas.
- **Ver qué se decidió:** en la consola, `window.__TERRANAUTA_I18N__` muestra el idioma, el origen (`url`, `saved`,
  `country`, `browser`, `default`) y el país detectado. En desarrollo también se imprime al cargar.
- **Empezar de cero:** la elección manual tiene prioridad sobre el país. Para volver a probar la detección, borrar
  `terranauta-lang` en DevTools → Application → Local Storage, o usar una ventana privada.
- **Idioma del navegador:** cambiar el idioma preferido del navegador (o, en Chrome/Edge DevTools → Sensors, el
  *Locale*) y abrir `/` sin `?country`.
- **Pruebas automáticas:** `npm run verify:i18n` comprueba los casos México, Estados Unidos, país desconocido,
  elección manual, enlaces directos, ausencia de bucles y que no falte ninguna traducción.

## Dónde están las traducciones

| Qué                                              | Archivo                                    |
| ------------------------------------------------ | ------------------------------------------ |
| Textos de interfaz (navegación, botones, alt…)  | `src/i18n/messages/es.ts` y `en.ts`        |
| Temas, submódulos, créditos de imágenes, recursos | `src/i18n/content/en.ts` (el español está en `src/data/`) |
| Slugs de URL traducidos y países hispanohablantes | `src/i18n/config.ts`                       |

- `en.ts` tiene el tipo `Messages`, derivado de `es.ts`: TypeScript avisa si falta o sobra una clave.
- Los componentes leen textos con `useMessages()` y datos con `useData()` (`src/i18n/I18nContext.tsx`).
- En los créditos se traducen solo las partes descriptivas («tripulación del Apolo 17» → «Apollo 17 crew»). Los
  autores, instituciones, URLs y licencias se conservan, y `npm run verify:i18n` lo comprueba.

### Para cuando llegue el backend

- **Datos:** `src/data/localized.ts` (`getDataApi(language)`) es el único punto de lectura de datos. Puede pasar
  a pedir `GET /api/...?lang=en` y devolver los mismos tipos sin tocar componentes. El backend puede guardar los
  textos con la forma de `ContentTranslation` (`src/i18n/content/types.ts`) o devolverlos ya traducidos.
- **Cuentas:** la elección de idioma vive en `localStorage`. Si más adelante se guarda en el perfil del usuario,
  basta con leerla en `bootstrap.ts` como `savedLanguage`.
